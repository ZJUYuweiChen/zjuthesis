\section{项目的主要内容和技术路线}

\subsection{主要研究内容}

\par 本研究围绕基于智能体的拖延症干预系统展开，试图设计一种交互式应用以解决拖延症问题。主要研究内容包括：

\par （1）智能体工作流架构设计：基于Spring AI Alibaba框架构建多智能体协作系统，采用图引擎进行工作流编排。系统配置多个推理型智能体，分别承担路由分发、简单/复杂项目对话、简单/复杂项目构建等职责，通过路由节点实现基于项目复杂度和聊天类型的智能路由。

\par （2）对话状态机与意图隔离机制：设计构建模式/对话模式/编辑模式三态交互模式，解决多轮对话中“任务构建意图”被闲聊打断的问题。构建模式中用户输入被视为需求补充，系统自动生成任务预览；对话模式允许基于已构建任务的自由探索；编辑模式支持任务结构的版本迭代。

\par （3）记忆持久化与上下文管理：采用基于 Redis 的断点持久化方案，实现基于Redisson分布式锁的多线程安全状态存储。配置摘要钩子进行长对话记忆摘要，当对话历史过长时自动触发摘要，保留最近若干条原始消息，确保上下文关联性与信息完整性。

\par （4）工具调用链可靠性保障：设计查询工具与操作工具分离架构，查询工具提供只读查询（获取项目、会话、标签、任务等），操作工具提供修改操作（创建/更新/删除任务等）。

\par （5）行为干预策略设计：基于微习惯理论和多巴胺设计原理，实现“方糖番茄钟”降低启动情绪成本；设计任务抽取随机推荐机制，利用变比率强化效应维持行为动机；构建积分与成就系统，通过即时反馈增强用户粘性。

\par （6）移动端前端设计：采用手绘风格营造温暖、亲切感，以黑白灰为主色调避免视觉压力。核心页面包括：首页（任务抽取入口）、任务清单页（紧急任务优先展示）、AI对话创建页（自然语言任务创建）、日历页（任务分布可视化）、专注页（方糖计时）、我的页（成就追踪）。

\subsubsection{后端架构}

\par 后端系统基于 Spring Boot 分层架构构建，按业务领域划分为用户模块、项目模块、智能体模块三大核心域。每个领域模块内部采用统一分层结构：Controller 层负责请求接入与响应、Service 层处理业务逻辑、Repository 层定义领域数据访问接口、基础设施层实现持久化细节。安全模块通过过滤器链拦截所有请求，完成认证后路由至对应领域控制器。持久化层采用 Redis 缓存与 PostgreSQL 主存的双存储策略，通过转换器实现领域实体与持久化对象的完全解耦。

\subsubsection{数据持久化方案}

\par 采用PostgreSQL + Redis混合持久化架构：PostgreSQL存储用户、项目、任务、标签、会话、消息等核心业务数据，使用UUID主键和TIMESTAMPTZ时区；Redis存储活跃会话状态和检查点数据，支持多线程安全和自动TTL过期。

\par Session生命周期：用户首次发起对话时自动创建，每次对话完成后更新draftProjectView，支持分页查询和批量删除。Chat生命周期：对话开始时保存用户消息，AI生成过程中实时流式推送，对话完成后保存完整AI回复，新会话首次调用时从历史加载消息注入检查点。

\subsection{可行性分析}

\subsubsection{技术可行性}

\par 本项目在技术上具有高度的可行性，依托于成熟且先进的开源框架与云原生服务，能够确保系统的稳定性与先进性。

\par 首先，在应用开发层面，项目选用了Spring AI Alibaba框架。该框架作为 Spring 生态的重要组成部分，为智能体（Agent）的开发提供了全方位的支持。它不仅内置了强大的推理型智能体能力，能够处理复杂的业务逻辑，还提供了基于图引擎的工作流编排功能，使得多步骤的任务执行流程清晰可控。此外，框架支持检查点（Checkpoint）持久化机制，保障了在长时间运行或系统故障时的状态恢复能力；同时，通过摘要钩子（Summary Hook）等功能，可以有效管理长对话历史，提升用户体验。这些特性为构建健壮的AI应用奠定了坚实的基础。

\par 其次，在模型选型方面，项目采用国产开源大模型，如 Qwen 和 DeepSeek。这些模型在中文语言理解、文本生成以及工具调用方面表现出色，能够精准地完成任务拆解、意图识别及自然流畅的对话交互。其开放的接口和活跃的社区生态，便于开发者进行定制化微调与集成，满足特定业务场景的需求。

\par 最后，在基础设施层面，依托阿里云平台提供的完整云服务矩阵，包括弹性计算 ECS、容器服务、云数据库 PostgreSQL 和 Redis 等，实现了从研发、测试到生产环境的全流程覆盖。PostgreSQL 以其强大的事务处理能力和扩展性，保障了结构化数据的可靠存储；Redis 则通过高效的内存读写，显著提升了系统响应速度。整体技术栈成熟稳定，社区支持完善，具备良好的可维护性与可扩展性。

\subsubsection{经济可行性}

\par 本项目在经济上具备良好的可行性，成本结构清晰，且具备较强的可控性。

\par 主要的运营支出来源于大模型 API 的调用费用。为有效控制成本，项目将采取多项优化策略：一是通过精细化设计提示词，提升指令明确性，减少无效生成与重试次数；二是合理设置模型参数，在保证输出质量的前提下降低资源消耗；三是采用流式输出方式，减少用户等待感知时间，提升并发效率；四是结合缓存机制，对高频重复请求进行结果复用，进一步降低 API 调用频次。通过上述措施，可在保障系统性能的同时，实现成本的最优管理，具有较高的投入产出比。

\subsubsection{时间可行性}

\par 项目计划周期约为 12 周，整体进度安排科学合理，具备较强的时间可行性。

\par 项目将严格按照“需求分析-架构设计-模块开发-系统集成测试”的逻辑主线有序推进。各阶段均设有明确的关键里程碑：第 1–2 周完成需求调研与分析；第 3–4 周完成系统架构与技术选型；第 5–8 周集中进行核心模块开发与接口联调；第 9–11 周开展系统集成、功能测试与性能优化；第 12 周完成部署上线及论文撰写收尾工作。各阶段任务边界清晰，可执行性强，并预留了一定的缓冲时间以应对潜在风险。在合理资源配置和有效项目管理下，完全能够在规定时间内高质量完成系统开发与学术论文撰写任务。
